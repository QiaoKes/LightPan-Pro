## 范围与需求

### R1 首次部署与重构范围
这是未部署的新 fork，不提供旧 115 配置、旧驱动标识或旧 STRM 的兼容迁移。允许移除被替代的 115 实现；不影响其他网盘正常功能。保留仍有用的现有架构及通用能力，不因“不兼容”重复建设。

### R2 纯 Go 运行与交付
所有必要 115 协议/API 使用 Go 实现。运行、构建和部署不引入 Python 服务或脚本依赖。本地 Python 源码仅作调研依据。记录必要的第三方来源和授权声明。

### R3 双凭据挂载
每个挂载一份 Cookie 和一套 Open 凭据（access/refresh token 及有效期），两者均需有效并属于同一 UID 才能完成首次挂载。允许多个独立挂载，本次不实现同挂载多凭据轮换或跨账号负载均衡。界面同时提供手工填写与扫码获取；缺少、失效或 UID 不匹配时明确拒绝保存为可用挂载。

### R4 登录、验证与凭据生命周期
复刻参考 Cookie 的设备选择、二维码获取、状态轮询、验证和 Cookie 取得流程；支持 Open 二维码授权、Token 兑换和刷新。等待、已扫码待确认（上游提供时）、成功、取消、过期、验证要求及网络失败均有明确表现。验证按上游真实能力处理，不伪造验证成功。重新授权一侧不得清空或覆盖另一侧；并发刷新与重新登录不能写回过时凭据。界面不要求用户手动拼接扫码返回结果。

### R5 请求模式忠实性
逐项对照业务调用及 SDK 的方法、端点、参数、UA/请求头、编码/加密、响应、缓存、节奏、重试和顺序。请求习惯以 EmbyNginx 为基线；不将看似重复的查询或等待直接删除。即使判断为缺陷，也须先记录源码、触发条件、参考行为、修改理由及测试，并在改变参考行为前获得用户确认；不得将此前的修复方向视为自行优化的通行授权。禁止将当前 SDK 默认行为未经比较直接替代参考项目行为；不承诺永不风控。

### R6 完整功能交付
本次包括登录、302 播放、路径/ID/pickcode 解析、目录树导出与解析、STRM、字幕/图片/NFO、增量事件监控。保留现有 115 文件管理、上传、跨盘和离线下载能力；以能力清单检查，不能借重构静默移除。无需复制参考项目无关商业授权或整套界面。

执行期用户确认 D9：115 删除按参考项目仅提供“移入回收站”，移除永久删除选项及其旧分支；不再以“先移入回收站再报永久删除未完成”作为永久删除能力。

### R7 模块职责
协议客户端负责请求；驱动负责网盘能力适配；认证服务负责凭据状态与刷新协调；播放层负责响应；Emby 适配层负责会话语义；STRM 负责本地任务产物。具体接口及文件所有权见 design.md、roadmap.md，公共模块不直接依赖 115 私有协议。

### R8 播放失败路由
媒体直链使用 Open。Token 过期按参考触发条件接入统一刷新协调；重试条件、次数和等待遵循对应参考分支，不套用自拟通用策略；失败返回可诊断错误，不自动换 Cookie 或其他账号。Cookie 获取目录树下载链接等专属调用不算媒体兜底。保留播放器 UA 语义与缓存隔离；请求合并不得合并不同设备语义的临时副本请求。不为每次播放额外探测 CDN。

### R9 运行期独立健康状态
首次挂载满足 R3 后，运行中分别管理 Cookie/Open 健康状态。Cookie 失效：提示重新登录，暂停依赖 Cookie 的树扫描和监控，有效 Open 播放继续。Open 失效：停止无法执行的 Open 操作，Cookie 独立能力仍可用。两侧均失效时相关远端操作不可用。用户手动禁用账号仍停止整个账号。一次网络超时不等同凭据永久失效。其他单凭据网盘认证行为保持不变。

### R10 目录树与 STRM
按参考调用流程导出目录树、轮询、下载、解析及生成 STRM。根目录、子目录、中文/特殊字符、空目录、取消和超时均需明确结果。路径引用与稳定 ID 区分；树中没有 ID 不得伪造 ID。扫描完整性决定是否可做缺失清理。只清理本次导出创建的云端临时对象和本地临时文件；清理失败独立记录，不误删源文件。

执行期用户确认 D11：补齐参考内置 charset_normalizer 3.5.1 的纯 Go 字符集探测及解码，通过 Python 离线对照验证后交付。不能以 UTF-8/BOM UTF-16/GB18030 三类编码近似实现替代此要求；本地内容解析不增加 115 请求。

### R11 输出归属与自动删除
新任务使用专用托管输出目录，禁止等同或祖先/后代重叠、根路径以及非空未托管目标。完整快照或已核实删除事件自动清理对应任务产物，无需默认关闭的删除开关。记录任务生成的 STRM 与下载附件归属；不删除未知手工文件或越过符号链接逃出任务目录。目录删除只处理托管后代及空目录。扫描失败、取消或不完整不能推断文件已删除。重命名/移动在任务范围内更新输出，移出范围清理原托管输出；新输出失败不得先丢失旧有效产物。

### R12 附件同步模式
字幕、图片、NFO 接入已有附件流程。新建 115 参考模式任务默认云端优先；对应托管附件跟随云端变化清理。用户显式选择本地优先/双向同步时，服从现有同步语义，事件处理不能另行绕过策略递归删目录。保持非托管文件并提示冲突。

### R13 增量监控
每个 STRM 任务按需开启，默认不自动开启；首次完整快照后启动，配合周期校准。支持重叠时间窗去重、持久化处理进度、重启续处理、重命名/移动及删除。事件和扫描统一协调，旧快照不得撤销已应用的新事件；只有处理完成才提交对应进度。Cookie 失效暂停，恢复后先校准缺失事件范围，不能以空响应当作全量删除。

### R14 Emby 多设备播放
参考同媒体不同设备播放时的临时副本策略，由 Emby 层依据真实会话判断，驱动执行复制/取链/清理。普通 STRM 或缺少会话信息时走普通取链，不凭 UA 猜测设备。临时副本明确记录所属任务/请求、远端文件 ID 和清理状态，失败与重启后可恢复清理，不删除原媒体。触发条件、复制参数、清理时序依照待核实的参考调用链冻结，不以 URL 缓存合并代替此行为。

## 专项验收：连续拖动播放
用户特别关注连续前后拖动后触发 115 风控。当前没有原故障日志或可复现样本，不将传闻归因于已确认代码缺陷。
- 固定账号、文件、UA、播放意图，直链未过期且无凭据/文件变更时，首次解析完成后连续 20 次前后拖动返回播放入口，不新增 Open downurl 调用，不触发 Cookie 媒体取链、临时复制或全目录扫描。元数据完整且缓存命中时，也不重复查询路径/文件信息。
- 同一缓存键首次并发请求只执行一次有效取链流程；过期后并发刷新合并，不因 Range 起止变化产生不同直链缓存键。
- GET/HEAD、UA变化、跨有效期、实际多设备播放分别统计，不能混为同一缓存命中场景。符合参考 Emby 多设备条件的临时副本单独验收。
- 302 模式不得进入服务端媒体分片拉取链；播放器对 CDN 的 Range 请求与 LitePan 的 API 请求分别观察。仅服务端日志不足以证明 CDN 请求行为。
- 遇到 401/403/405/429，记录阶段（控制 API/CDN）、响应与重试次数，不能把所有播放失败直接认定为账号风控。不对拖动错误无限刷新/切 Cookie。
- 实际播放器测试需记录入口次数、元数据查询次数、downurl 次数、刷新次数及客户端可观察的 Range/重试情况；验证一次通过不代表永不风控。该场景归属 W5/W8，补充 A4/A11。
